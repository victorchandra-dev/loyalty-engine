# LoyaltyFlow restart plan (Tue 29 Sep – Fri 2 Oct 2026)

**Goal:** by Friday, LoyaltyFlow runs on the Amada Flow store as a private app
hosted on Cloud Run, with the bugs that lose points or money fixed.

**Background:** bugs 1–5 come from
`amadaflow.com/claudedocs/analysis_loyaltyflow_2026-09-29.md`. Bugs 6–11 were
found in a code read on 2026-09-29.

## Decisions (confirmed by the owner on Wed 30 Sep)

| Decision | Choice |
|---|---|
| App Store | No. This is a private app for Amada Flow only |
| Infrastructure | **Everything the engine runs on is in GCP:** Cloud Run, Cloud SQL Postgres, Secret Manager, Cloud Logging and Error Reporting. Supabase isn't used for the engine; the storefront keeps using it for its own features. |
| What Friday means | Soft launch: the app runs on the live store, the storefront stays `coming_soon`, and staff place test orders. Open to customers on Monday |
| Existing customers | Start at 0 points, with their tier set from lifetime spend |
| Move metaobject definitions into the TOML | Skip |

Things that stay outside GCP by design: the storefront runs on Shopify
Oxygen, and points and program data live in Shopify metafields and
metaobjects. The database only holds login sessions and the processed-webhook
keys. Nothing in it is irreplaceable: losing it means the admin logs in again.

## Wednesday: fix the bugs that lose points or money (done Thu 1 Oct AM)

- [x] Added the `ProcessedWebhook` table and its migration
      (`20261001000000_processed_webhook`). `app/loyalty/run-once.server.ts`
      claims the key first, returns 'duplicate' if it already exists, and
      releases it if the work throws.
- [x] Order, refund and redeem handlers read the program from the shop
      snapshot (`loadProgramSnapshot`). They read the customer in one query
      (`loadLoyaltyCustomer`): balance with `compareDigest`, state, reward,
      referral and spend.
- [x] Every points change is one `saveLoyaltyCustomer` (a single atomic
      `metafieldsSet`) that includes the referrer's balance, and each balance
      carries its `compareDigest`. If the balance changed in between, the
      write fails and Shopify retries.
- [x] Removed `lastOrderId`, `signupAwarded`, the reconcile tool and its UI,
      `markRefereeReferralCredited`, `creditReferrerForFirstPaidOrder`,
      `clearRedemptionForCustomer`, and the four layers of sync functions.
- [x] Bug 1: a failed read returns 500 and writes nothing.
- [x] Bug 2: `orders/paid` clears a reward that was redeemed before the order
      was created. Bug 8: redeeming returns 409 while a reward is active.
      **Kept the 24-hour expiry:** the storefront needs `expiresAt` to show a
      reward. Since the reward is cleared once used, the open question about
      the Shopify Functions clock no longer matters much.
- [x] Bug 4: refunds now read `order_id` and the top-level `transactions`,
      look up the customer from the order, and use the refund GID as the
      duplicate key. Limit: without `read_all_orders`, refunds on orders older
      than 60 days find no customer and are skipped.
- [x] Bug 7: customer sync skips a customer it can't read and keeps every
      one-time award. The admin message says how many were skipped.
- [x] Bug 10: the automatic discount is created whenever a program exists.
- [x] Tests: 84 passing in 13 files, including routes for orders, refunds and
      redeem, duplicate deliveries arriving at once, a digest mismatch, the
      referral write, sync and the discount. Typecheck and lint are clean.
- [x] GCP (after the owner logs in and approves): enable the Cloud Run, Cloud
      SQL Admin, Secret Manager, Artifact Registry and Cloud Build APIs. Create
      Cloud SQL `loyalty-pg` (Postgres 16, `db-f1-micro`, `asia-southeast1`,
      public IP with no authorized networks, so it's only reachable through the
      Cloud Run connector). Then create database `loyalty` and set the user's
      password. It takes about 10 minutes, so start it early. If an org policy
      blocks public IP, use the private-IP path in `docs/deploy-cloud-run.md`.
